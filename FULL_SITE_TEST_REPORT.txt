Tablet Masters - full-site testing and deployment
Date: 9 November 2026 (Asia/Singapore)

Scope
All 17 public pages of tablet-masters.com were tested on desktop Chromium and
mobile Chrome (Pixel 7 emulation), together with admin pages, navigation, the
cart, customer forms, internal links/assets, screenshots, offline behavior,
malformed requests, and payment integration. External sites linked from the
project were outside this audit.

Repairs and updates
- The financial dashboard previously rendered without authentication. Orders
  now require a valid admin session before reading financial/customer data.
- Removed the built-in production admin password. Authentication supports a
  password hash in private configuration, renews the session ID at login, uses
  HTTP-only/SameSite cookies, and invalidates sessions from old credentials.
- Added Apache rules to deny direct access to includes/configuration, source
  directories, repository metadata, databases, logs, and backup files.
- Restricted service-worker caching to public pages and static assets. Admin
  screens, receipts, registrations, personal query strings, failed responses,
  and private/no-store responses are excluded. The cache version was updated
  so old application caches are removed on activation.
- Reproduced a PHP type error from malformed repair form fields and corrected
  the repair, school, healthcare, conference, registration, and forum handlers.
  Malformed input now fails validation without sending messages or showing
  PHP errors.
- Added safe scalar query-parameter handling for registration, school,
  healthcare, conference, accessory, and review pages. Array-valued query
  parameters no longer break pages or emit conversion warnings.
- Included all payment repairs from PAYMENT_TEST_REPORT.txt: verified payment
  confirmation, cart/preference preservation, strict checkout validation,
  delayed paid events, locked webhook deduplication, complete line-item
  retrieval, SMS consent, and registered-device activation/cancellation retry.
- Expanded Playwright coverage for forms, authentication boundaries, malformed
  requests, Apache restrictions, offline privacy, and an opt-in real Stripe
  sandbox redirect. Live test timeouts allow for remote network latency.
- Replaced direct recursive SCP deployment with a verified runtime manifest,
  private staging/backups, server PHP linting, checksum verification, atomic
  file replacement, and rollback on application/verification failures.
- Updated testing/deployment documentation and ignored generated results,
  customer databases/logs, configuration backups, and compiled Python files.

Validation
Local full-site suite: 103 passed, 3 expected skips.
  The skips were the desktop mobile-menu check and two Apache-only checks.
Payment suite: 104 passed on the final release code, using the isolated local
  application and Stripe simulator, with real PHP endpoints and SQLite state.
Deployment transaction checks: 4 passed, covering configuration/inventory
  preservation, private password setup, path rejection, and rollback.
Syntax: 25 changed/new PHP files passed lint; JavaScript, Python, PowerShell,
  and git diff whitespace checks also passed. All staged runtime PHP files
  were additionally linted by the server's PHP interpreter before deployment.
Final live result: 107 passed, 0 failed, 1 expected desktop/mobile-menu skip.
  This post-deployment run took approximately 4.5 minutes, with two workers
  and no retries. Both real Stripe sandbox Checkout redirect checks passed.
  All public pages, admin boundaries, form checks, screenshot comparisons,
  Apache access restrictions, malformed requests, and offline privacy passed.

Limits
The sandbox redirect checks do not complete a real Stripe-hosted payment.
3-D Secure, live charges, active subscription renewal/cancellation, refunds,
tax/shipping configuration, and real email/SMS delivery remain outside these
checks. Successful business inquiry submissions were blocked or tested with
invalid data to avoid sending unsolicited messages or creating production
customer records. Earlier payment testing used a fully isolated simulator.
